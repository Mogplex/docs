`POST https://www.mogplex.com/api/v1/mogplex/mcp`

The Mogplex Cloud API is exposed as an MCP server over JSON-RPC 2.0. The MCP
tools call the same user-scoped service layer as the v1 REST API, so Mogplex
continues to own sandbox launch, automation validation, execution, and logs.

<Callout type="info">
  Looking for the external MCP servers configured inside Mogplex, such as
  Linear or Supabase? That is a different endpoint: see
  [GET /api/v1/mogplex/mcp/servers](/web/api/mcp-servers).
</Callout>

## Connect with OAuth

OAuth 2.1 authorization code with PKCE is the preferred path for local agents:

```bash
codex mcp add mogplex \
  --url https://www.mogplex.com/api/v1/mogplex/mcp \
  --oauth-resource https://www.mogplex.com/api/v1/mogplex/mcp
codex mcp login mogplex
```

The client discovers Mogplex's protected-resource metadata, dynamically
registers itself with the authorization server, and opens the Mogplex consent
screen. See [Install Mogplex MCP](/mcp/install) for Codex,
Claude Code, Cursor, and troubleshooting instructions.

Mogplex validates the OAuth token's issuer, signature, expiry, client id,
audience, allowlist admission, and linked Mogplex profile. An unauthenticated
request receives a `401` and a `WWW-Authenticate` challenge with the protected
resource metadata URL.

## PAT fallback

Clients without remote MCP OAuth support can send a personal access token:

| Header | Value |
| --- | --- |
| `Authorization` | `Bearer mog_...` |
| `Content-Type` | `application/json` |
| `Accept` | `application/json, text/event-stream` |

PAT scopes apply to the underlying operation: reads require `read`; mutations
require `write`. OAuth grants access through the browser consent flow.

## Methods

| Method | Description |
| --- | --- |
| `initialize` | Return server info, capabilities, protocol version, and instructions. |
| `notifications/initialized` | Acknowledge client initialization with HTTP `202`. |
| `ping` | Return an empty object. |
| `tools/list` | Return the current tool definitions and JSON schemas. |
| `tools/call` | Validate arguments and invoke one tool. |

The server advertises MCP protocol version `2025-11-25` and returns the
`mcp-protocol-version` response header. It is stateless: clients do not need an
MCP session id.

## Initialize

```bash
curl -sS \
  -X POST \
  -H "Authorization: Bearer $MOGPLEX_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize"}' \
  https://www.mogplex.com/api/v1/mogplex/mcp
```

The result includes:

```json
{
  "protocolVersion": "2025-11-25",
  "capabilities": { "tools": { "listChanged": false } },
  "serverInfo": { "name": "mogplex", "version": "0.1.0" }
}
```

## Tools

### Discovery and sandboxes

| Tool | Scope | Important arguments |
| --- | --- | --- |
| `mogplex_list_repos` | `read` | Optional `query`, `limit` (1–200). |
| `mogplex_list_agents` | `read` | None. |
| `mogplex_list_models` | `read` | None. |
| `mogplex_list_sandboxes` | `read` | Optional `repoId`, `status`, `limit` (1–200). |
| `mogplex_create_sandbox` | `write` | Required `repoId`; optional branch and root-directory fields. |
| `mogplex_get_sandbox_logs` | `read` | Required sandbox record `sandboxId`. |

`mogplex_create_sandbox` creates or reuses a repo/branch sandbox. It consumes
the existing launch event stream and returns when the sandbox record is ready
or launch fails; the MCP server does not add a polling loop.

### Automations

| Tool | Scope | Important arguments |
| --- | --- | --- |
| `mogplex_list_automations` | `read` | Optional `limit` (1–100, default 50) and opaque `cursor`. |
| `mogplex_get_automation` | `read` | Required `automationId`. |
| `mogplex_create_automation` | `write` | Required positive integer `installationId`; optional metadata, graph, and `publish`. |
| `mogplex_update_automation` | `write` | Required `automationId`; optional metadata, positive integer `installationId`, and graph. |
| `mogplex_publish_automation` | `write` | Required `automationId`. |
| `mogplex_set_automation_model` | `write` | Required `automationId`, `nodeId`, and enabled `modelId` or `null`; optional `publish`. |
| `mogplex_trigger_automation` | `write` | Required `automationId` and `repoId`; optional `input` and `idempotencyKey`. |
| `mogplex_list_automation_runs` | `read` | Required `automationId`; optional `limit` (1–50). |
| `mogplex_get_automation_run_logs` | `read` | Required `automationId` and `runId`. |

Automation listing is deliberately bounded and returns graph-free summaries.
Pass `nextCursor` from one result back as `cursor`, and call
`mogplex_get_automation` only when you need the full draft and published
graphs.

Create and update accept only a complete Flow graph with `nodes` and `edges`
arrays plus an optional valid `viewport`. Malformed values are rejected before
the draft is changed. The create and update `installationId`, when supplied,
must be a positive safe integer. Publishing performs the stricter executable
graph checks and creates an active version.

### Agent runs

| Tool | Scope | Important arguments |
| --- | --- | --- |
| `mogplex_start_agent_run` | `write` | Required `repoId` and `prompt`; optional harness, branch, root directory, and idempotency key. |
| `mogplex_get_run` | `read` | Required `runId`. |
| `mogplex_get_run_events` | `read` | Required `runId`; optional `limit` (1–200). |
| `mogplex_cancel_run` | `write` | Required `runId`. |

## Call a tool directly

```bash
curl -sS \
  -X POST \
  -H "Authorization: Bearer $MOGPLEX_TOKEN" \
  -H "Content-Type: application/json" \
  -H "Accept: application/json, text/event-stream" \
  -d '{
    "jsonrpc": "2.0",
    "id": 42,
    "method": "tools/call",
    "params": {
      "name": "mogplex_list_automations",
      "arguments": { "limit": 20 }
    }
  }' \
  https://www.mogplex.com/api/v1/mogplex/mcp
```

Successful tool results include both human-readable text and structured JSON:

```json
{
  "jsonrpc": "2.0",
  "id": 42,
  "result": {
    "content": [{ "type": "text", "text": "Found 0 Mogplex automation summaries." }],
    "structuredContent": { "automations": [] }
  }
}
```

## Errors

| JSON-RPC code | HTTP | Meaning |
| --- | --- | --- |
| `-32700` | 400 | Parse error: invalid JSON. |
| `-32600` | 400 | Invalid JSON-RPC request. |
| `-32601` | 200 | Method or tool not found. |
| `-32602` | 200 | Invalid tool arguments. |
| `-32001` | 401 | Missing or invalid OAuth/PAT authorization. |
| `-32002` | 429 | Rate limit exceeded. |
| `-32003` | 403 | Forbidden browser origin. |
| `-32603` | 200 | Internal error. |

Failures from an underlying Mogplex API operation, including insufficient PAT
scope, are returned as MCP tool results with `isError: true` and structured
error content.

## CORS

Same-origin requests pass automatically. Browser requests from other origins
must match `MOGPLEX_MCP_ALLOWED_ORIGINS`. Native local clients generally omit
the `Origin` header and do not require a CORS entry.
